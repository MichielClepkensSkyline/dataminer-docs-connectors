# Starlink Enterprise - Service Group

## About

The Starlink Enterprise - Service Group connector is exported by the parent connector [Starlink Enterprise](xref:Connector_help_Starlink_Enterprise). For each known service group, a separate child element (or "DVE", i.e., dynamic virtual element) using this connector will automatically be created. These DVEs contain only data related to the service group.

## Configuration

### Initialization

The element using this connector can only be created by the parent element using the [Starlink Enterprise](xref:Connector_help_Starlink_Enterprise) connector. No additional configuration is necessary.

## How to Use

This connector is automatically generated by the Starlink Enterprise connector, range 1.1.0.x. For each entry in the **Service Group DVEs** table, a separate dynamic virtual element (DVE) can be created.

An element is automatically created when a new **Group Name** is set in the **Services** table of the parent element.

This connector cannot be used to create a standalone element. You need to create a parent element using the Starlink Enterprise connector to be able to see the exported child elements.

### User Terminals Page

The User Terminals page contains the **User Terminals** table. This table shows the Starlink terminals that are linked to the accounts for which a Starlink Enterprise Account element is actively querying the Starlink API. Telemetry is polled every minute and stored using history sets for accurate backpolling.

If the **Uptime** column for a user terminal shows **Offline**, it was returned by the Management API and not by the Telemetry API. This means no telemetry (Signal Quality, Downlink Throughput, etc.) can be shown for it.

#### Device Name

If a service is active on the user terminal, the **Device Name** column will show the service nickname.

If no service is active, the device ID is used as the device name.

Changing the device name from the User Terminals table is currently not possible. To change it, you will need to use the Starlink web interface. The new name will then appear in the table after the next poll cycle.

#### Location Information

The **Latitude** and **Longitude** combination represents a coordinate near the user terminal, but this is not the exact location.

The longitude is calculated based on the H3 cell that is returned by the API (H3 geospatial indexing system). This H3 cell ID represents the center point of a hexagonal area, not the exact coordinates of a specific location within that area. If the exact location of the terminal is somewhere else within the hexagon, the latitude and longitude will differ.

#### User Terminal Reboot

You can reboot a user terminal by clicking the **Reboot** button.

You can verify the reboot by checking if the **Uptime** column resets to zero. However, note that this will only be reflected after the next polling cycle.

#### Hidden/Empty Columns

The columns **User Terminal Device ID**, **Account Number**, **Service Line Number**, **State**, **User Terminal DVE ID**, and **Service Group DVE ID** in the User Terminals table are hidden by default. You can show them by right-clicking the table column header, selecting **Columns**, and then selecting the columns you want to show.

For terminals that are not assigned to a service group, the hidden **Service Group DVE ID** column may be empty or show *Not initialized*. Only terminals that are assigned to a service group do have a value in this column.

#### Logging

When the **Info Logging Level** of the element log file is raised to *Level 1* or higher, a line will be added to the log file in the following cases:

- When one or more terminals are still in the User Terminals table but were not returned by the API.
- When no terminals are assigned to a specific account.

### Service Line Statistics Page

Each row in the **Service Line Statistics** table represents aggregated KPI data for the terminals that belong to that service line.

### Alerts Page

Each row in the **Alerts** table represents an alert that comes from a user terminal or from a router. Alerts will persist for as long as they are active.

The columns **User Terminal Device ID**, **Router Device ID**, and **Alert Kit Number** in the Alerts table are hidden by default. You can show them by right-clicking the table column header, selecting **Columns**, and then selecting the columns you want to show.

### Routers Page

Information related to routers is stored in the **Routers** table.

The **Account Number** column in the Routers table is hidden by default. You can show it by right-clicking the table column header, selecting **Columns**, and then selecting this column.

When the **Info Logging Level** of the element log file is raised to *Level 1* or higher, you will see a line in the log file when one or more routers are still in the table but were not returned by the API.

### IP Allocations Page

Information related to IP allocations is stored in the **IP Allocations** table.

The **IP Allocation Device ID** column in the IP Allocations table is hidden by default. You can show it by right-clicking the table column header, selecting **Columns**, and then selecting this column.

### Services Page

The rows in the **Services** table represent the active service plans of the accounts.

#### Hidden/Empty Columns

The **Group DVE ID** column in the Services table is hidden by default. You can show it by right-clicking the table column header, selecting **Columns**, and then selecting this column.

For services that are not assigned to a service group, the **Group Name** and **Group DVE ID** column may be empty or show *Not initialized*. Only services that are assigned to a service group do have a value in these columns.

#### Logging

When the **Info Logging Level** of the element log file is raised to *Level 1* or higher, you will see a line in the log file when no services are active for a specific account.

#### Triggering a Top-Up

If you need to purchase additional data beyond the included monthly allocation, you can trigger a top-up from within the Services table.

To do so, specify the number of data blocks you want to top up for a specific account in the **Data Blocks to Add** column of the Services table, and then click the **Top Up** button in the row. This will execute a one-time top-up request via the Starlink Management API. The connector will validate the product availability and confirm whether the top-up succeeded or failed.

Because the Starlink Enterprise element relies on a Starlink Enterprise Account element to send the Opt In/Out request to the Starlink API, it may take a minute or two for the **Automatic Top Up** toggle button to update after it is used. This is due to the buffer mechanism that was added to allow inter-element communication. Please keep these background actions in mind when toggling that button.

### Overage Lines Page

This table shows the overages, which are additional services or data consumed beyond the limit.

The **Service Line Number** column in the Overage Lines table is hidden by default. You can show it by right-clicking the table column header, selecting **Columns**, and then selecting this column.

### Monthly Data Usage Page

On this page, you can review and monitor your data usage per month by type of data consumed.

The columns **Priority Data**, **Standard Data** and **Service Line Number** in the **Monthly Data Usage** table are hidden by default. You can show them by right-clicking the table column header, selecting **Columns**, and then selecting the columns you want to show.

### Daily Data Usage Page

On this page, you can review and monitor your data usage per day by type of data consumed.

The columns **Priority Data**, **Standard Data** and **Service Line Number** in the **Daily Data Usage** table are hidden by default. You can show them by right-clicking the table column header, selecting **Columns**, and then selecting the columns you want to show.
